# Запись решения (ADR)

Ты оформляешь решение так, чтобы владелец, который не читает код, мог его утвердить или отклонить.
Пиши по-русски, коротко, на языке последствий: что изменится, что будет при ошибке, как откатить.

## Шаг 1. Определи тип решения

**Необратимое**, если выполняется хотя бы одно: отмена потребует больше дня работы или данных не вернуть;
затрагивает формат данных, публичный интерфейс, структуру проекта, безопасность или деньги; добавляет
новую зависимость (пакет); на решении будут строиться другие части.

**Обратимое**: можно отменить небольшой правкой без последствий для данных и других частей.

Если сомневаешься, считай необратимым.

## Шаг 2. Создай запись

Название бери из аргумента (`$ARGUMENTS`), иначе сформулируй сам: коротко, по-русски, без точки в конце.

```bash
sh "${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.cmd" ../skills/adr/scripts/adr.py <<'JSON'
{"command": "new", "project_dir": ".", "title": "НАЗВАНИЕ", "type": "irreversible"}
JSON
```

Для обратимого решения подставь `"type": "reversible"`. Команда сама выберет номер, создаст файл
`docs/adr/NNNN-название.md` из шаблона и обновит индекс `docs/adr/README.md`.

## Шаг 3. Заполни запись

Открой созданный файл и заполни разделы: «Контекст», «Решение», «Последствия для владельца»,
«Рассмотренные альтернативы». Для необратимого решения обязательно заполни «Объяснение для владельца
(одна страница)»: простыми словами, без терминов, с ответами на вопросы: что за решение, что изменится,
что будет при ошибке и сколько будет стоить исправление, как откатить, что нужно от владельца.
Для обратимого решения этого раздела в файле нет. Удали подсказку «Как пользоваться».

## Правила

- **Статус всегда `proposed`.** Статус `accepted` ставит только владелец. Не меняй его и не пытайся обойти
  защиту: попытка потребует подтверждения владельца.
- Принятые ADR не правятся. Если решение нужно пересмотреть, создай новый ADR.
- В конце сообщи владельцу одной-двумя фразами, какой ADR создан, какого он типа и что ждёт утверждения.
