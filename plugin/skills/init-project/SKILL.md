# Подключение проекта к ProjectArchitect

Ты помогаешь владельцу подключить проект. Владелец не программист: говори по-русски, коротко, на языке
последствий (что появится, что изменится, как откатить), без терминов реализации.

## Шаг 1. Задай вопросы о проекте

Если доступен инструмент AskUserQuestion, используй его, иначе спроси в чате. Не больше пяти вопросов в
этом шаге и не спрашивай то, что уже ясно из ответов.

1. **Как называется проект и что он делает?** Одна-две фразы своими словами.
2. **На каких языках он пишется?** Варианты: Python, TypeScript, C#, PowerShell (можно несколько).
3. **Что для вас важнее всего?** Например: надёжность, скорость разработки, низкая стоимость, понятность,
   безопасность данных (можно несколько).
4. **На какой системе вы работаете с проектом (целевая ОС)?** Варианты: Windows 11, macOS, Linux. Объясни
   одной фразой, зачем: на этой системе ИИ проверяет проект при каждой сессии бесплатно, а проверки в
   облаке (CI) всегда идут на Linux и ловят то, что привязано к одной системе. Ответ попадёт в
   `docs/CONSTITUTION.md`.
5. **Код уже есть?** Если да, после подключения предложи `/parch:analyze-existing`. Папка проекта по
   умолчанию текущая (`$ARGUMENTS`, если передан аргумент); спрашивай про неё, только если это неясно.

## Шаг 2. Поговори о цели продукта

Это самый важный шаг: без утверждённой цели планирование не начинается. Задай владельцу по очереди (по одному
вопросу, можно переформулировать, если ответ неясен), и запиши ответы его же словами:

- **Для кого продукт?** Кто им будет пользоваться.
- **Когда продукт можно считать готовым?** Нужен хотя бы один проверяемый критерий: по нему можно честно
  сказать «выполнено» или «нет». Если владелец отвечает общими словами, предложи 2–3 конкретных варианта.
  Каждый критерий станет пунктом G1, G2… в `docs/GOAL.md`.
- **Что в продукт точно НЕ входит?** Это защищает от расползания объёма. Можно пропустить, если владелец не
  знает.

## Шаг 3. Выполни подключение

Запусти команду, подставив ответы владельца в JSON. Языки пиши латиницей: `python`, `typescript`,
`csharp`, `powershell`. Целевая ОС: `windows`, `macos` или `linux`. Команда ничего не перезаписывает:
существующие файлы она пропускает.

```bash
sh "${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.cmd" ../skills/init-project/scripts/init_project.py <<'JSON'
{
  "project_dir": ".",
  "name": "НАЗВАНИЕ",
  "languages": ["python"],
  "description": "ЧТО ДЕЛАЕТ ПРОЕКТ",
  "priorities": "ПЕРВОЕ ВАЖНОЕ\nВТОРОЕ ВАЖНОЕ",
  "target_os": "windows",
  "goal": {
    "summary": "ЧТО ЭТО ЗА ПРОДУКТ",
    "audience": "ДЛЯ КОГО",
    "criteria": ["ПЕРВЫЙ КРИТЕРИЙ ГОТОВНОСТИ", "ВТОРОЙ КРИТЕРИЙ"],
    "out_of_scope": ["ЧТО НЕ ВХОДИТ"]
  }
}
JSON
```

Если команда сообщила, что не найден Python или нет `sh`, остановись и скажи владельцу об этом простыми
словами: подключение не выполнено, нужно поставить Python 3.12 или новее (на Windows ещё и Git for Windows),
затем повторить. Если команда отказалась из-за ответа (например, нет критерия готовности), задай владельцу
недостающий вопрос и повтори. Потом предложи запустить `/parch:doctor`.

## Шаг 4. Расскажи, что получилось

Ответь владельцу коротко, по-русски:

- что создано (цель в `docs/GOAL.md`, `docs/CONSTITUTION.md` с целевой ОС и версиями инструментов, документы
  в `docs/`, CI, правила защиты) и что пропущено, потому что уже было;
- **цель `docs/GOAL.md` пока черновик**: попроси владельца прочитать её и, если всё верно, утвердить (заменить
  строку статуса); без этого планирование блоков не начинается;
- **передай владельцу инструкцию про CircleCI из отчёта команды дословно, пунктами В1–В5 в том же порядке**
  (доступ приложения, проект в CircleCI, автоотмена, защита `main` после первого зелёного `check`, ключ записи табло
  только после защиты): это действия самого владельца, ИИ их выполнить не может; порядок менять нельзя. Если вместо
  инструкции в отчёте пометка «Файл .circleci/config.yml уже был», передай её дословно и скажи, что В1–В5 пока
  выполнять не нужно: сначала добавьте задания проверок или удалите файл и повторите init;
- остальные замечания из отчёта команды;
- что нужно сделать дальше: закоммитить файлы (в сообщении коммита должны быть разделы «## Основания» и «## Защищённые
  файлы, изменённые в PR»: подключение меняет `.github/`, `.circleci/`, `.claude/`, `state/`, `docs/CONSTITUTION.md`,
  `docs/GOAL.md`, `AGENTS.md`; назовите папки целиком и зачем, иначе проверка `standard` в CI красная) и один раз
  запустить `/parch:doctor`, чтобы убедиться, что защита
  работает на этом компьютере.

Не правь `docs/CONSTITUTION.md` и `docs/GOAL.md` после создания: это файлы владельца, защита потребует его
подтверждения.
