## Ход приёмки

Проект прогона: приватный репозиторий `pete-doc/parch-e2e-test-2`, блок F1 «Перевод метров в футы и обратно» (цель G1).
CI шёл на CircleCI (ADR-0022), а не на GitHub Actions: критерий 4 принят в этом смысле (проверка `ci/circleci: check`
на Ubuntu, Linux-образ `cimg/python:3.12`). Число прогонов превысило заранее названное (в CircleCI они идут с
номерами от #1 до #8 на 2026-10-08, часть запущена вручную; расход кредитов здесь не записан, он виден в Plan Usage):
критерий принят владельцем с этим отступлением. Каждый красный прогон нашёл настоящую проблему продукта (см. ниже),
лишних «посмотреть» прогонов не было.

- Подключение и цель: PR 1 (init, цель G1, CI на CircleCI, защита `main`), слит 2026-10-07.
- Функция и тест: PR 2 `F1: перевод метров в футы и обратно (функция, тесты, baseline)`, слит коммитом `7f461d8`
  (2026-10-08). Тест написала роль `tester` (22 теста, отдельный коммит), функция была от `implementer`; «Основания»
  в коммитах. Итоговый `ci/circleci: check` зелёный.
- Заведомое нарушение: PR 3 (удалён `test_100_feet_is_30_48_meters`, он в baseline). `parch tests` красный:
  «Число тестов уменьшилось: в baseline 23, найдено 22 … Тест нельзя удалять, чтобы «починить» проверки»; статус
  слияния `BLOCKED`. Закрыт без слияния по слову владельца 2026-10-08.
- Ревью: `/parch:review` на PR 2, комментарий https://github.com/pete-doc/parch-e2e-test-2/pull/2#issuecomment-6051911605
  (4 замечания, пересказаны владельцу; два из них стали находками № 7 и № 8).
- Табло: после слияния PR 2 задание `state` на `main` само обновило ветку `status`; `state/STATUS.md`: «1 из 1 блоков
  готово · критерий G1 выполнен», тестов 23 (было 1), упавших и пропущенных 0. Владелец проверил красный крест PR 3 и
  `STATUS.md` лично.

### Найдено 8 проблем продукта

1. Роли `tester` не было в плагине, поэтому тест не мог написать никто: роль добавлена (PR 71, выпуск 0.1.9).
2. Охрана путей для `tester` была слишком широкой и давала ложные блоки: строгая охрана и таблица команд (PR 72, 0.1.9).
3. `init` для Python не создаёт пакет `src/<имя>/` и `.importlinter`: первый PR с кодом красен на `architecture`
   без предупреждения. **Не исправлено**, записано в `docs/BACKLOG.md` (находка 3 прогона F20).
4. Проверка `duplicates` падала на коротком коде (`--fail-on-empty`), на Windows не находился `npx`: исправлено
   (PR 74, 0.1.10).
5. Тесты проверялись `python -m pytest`, CI запускает `pytest` (скрыт `ModuleNotFoundError`): исправлено в `tester.md`,
   `init`, шлюзе Stop; автоматика `tests/test_command_parity.py` (PR 74, 0.1.10).
6. Шаг В2 не проверял триггер pipeline в CircleCI: без него CI не стартует ни на PR, ни на слияние в `main`: текст
   исправлен (PR 74, 0.1.10), триггер создан владельцем 2026-10-08.
7. `tester` писал «заведомо плохие примеры», которые не вызывают код проекта: следующий PR продукта.
8. Описание PR не называет изменённые защищённые файлы (`.github/parch/parch_ci.py` в PR 2): следующий PR продукта.
