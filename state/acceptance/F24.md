# Приёмка F24. Шаблоны CI на CircleCI

Блок принимает только владелец: когда все критерии отмечены и ниже стоит строка «Итог: принято владельцем, ДАТА», блок становится
«готово» на табло (тесты `tests/test_circleci_templates.py` при этом тоже должны проходить). Пока строки нет, блок ждёт вас: тесты
проверяют файлы и поведение скриптов на временных репозиториях, а работу на настоящем CircleCI проверяет только живой прогон F20.
Спецификация: `docs/specs/F24-circleci-templates.md`, решение: ADR-0022 (должно быть принято владельцем).

## Критерии

Отмечает только владелец: `[x]` да, `[ ]` нет или не проверено; рядом дата.

- [ ] Шаблон CircleCI на новом проекте: итоговая проверка `ci/circleci: check` зелёная на первом PR (дата: )
- [ ] Условие приёмки: на живом проекте с несколькими языками при падении одного из них итоговый `check` красный, слить нельзя (дата: )
- [ ] «Основания» из коммитов ветки на живом проекте: ветка без раздела красная с понятным сообщением, ветка с разделом в одном коммите зелёная (дата: )
- [ ] Workflow `ci` не запускается на ветке `status` (после слияния нет лишнего прогона) (дата: )
- [ ] Табло публикуется после слияния: задание `state` зелёное, `state/STATUS.md` на ветке `status` обновился (дата: )
- [ ] Без ключа записи `state` пишет «ключ записи не подключён, табло не опубликовано, шаг В5 в инструкции», а не падает с неясной ошибкой (дата: )
- [ ] Проект без тестов зелёный: код 5 pytest при отсутствии тестов не делает `state` красным (дата: )
