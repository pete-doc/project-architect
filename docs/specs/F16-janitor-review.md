# Спецификация F16. Janitor и ИИ-ревью агентом внутри Claude Code

Статус: утверждена владельцем, 2026-10-05 (с ответами на вопросы, они внесены ниже). Критерии цели: G2 (ИИ не обходит
проверки) и G6 (не теряет нить). В реестре блок зависит от F13 (готово) и F14: до готовности F14 он не может стать «готово», но
работа над первым PR технической зависимости от F14 не имеет (ревьюеру нужны только PR и спецификация).

## Зачем

Две вещи проверка CI сама не умеет. Первая: мёртвый код копится, потому что убирать его страшно и скучно. Вторая: тесты и
код пишет ИИ, и CI видит только, что тесты проходят, а не что они проверяют нужное (раздел 12 стандарта). Блок добавляет
двух помощников: **уборщика** (janitor) и **ревьюера**. Оба работают внутри Claude Code, по вашей подписке, без платного API
в CI (решение владельца).

## Что вы получите

- **Роль `reviewer`** (до 40 строк) и команда `/parch:review НОМЕР_PR`: читает PR в чистом контексте (без чата, который писал
  код), только на корректность и соответствие спецификации, и оставляет комментарий в PR: «замечаний нет» или список по
  существу. Стиль и вкусовщину не обсуждает.
- **Ревью обязательно для PR, которые сливаете вы сами**: те, что затрагивают список из ADR-0003 (раздел «Слияние PR» в
  `AGENTS.md`: `.github/`, `.claude/`, hooks, агенты, `templates/ci/`, тесты кроме новых, `AGENTS.md`, `CLAUDE.md`, baseline,
  `state/acceptance/`, правила проверок в `pyproject.toml`) или содержат ADR со статусом `proposed`. Рабочая сессия запускает
  `/parch:review` до того, как просит у вас «сливай», и пересказывает результат по-русски на языке последствий: что нашли, чем
  это грозит, что решить вам. Остальные PR без обязательного ревью (его можно запросить командой).
- **Роль `janitor`** (до 40 строк): берёт мёртвый код, который вы утвердили поимённо (ответ «Б» в `QUESTIONS.md` или список
  в `state/`), и открывает маленькие PR на удаление: один кандидат на PR, архивная метка `archive/ИМЯ-ДАТА` в git до удаления,
  доказательство (запрос поиска и его результат) в описании. Модули со статусом `keep-until` и всё без вашего «да» не трогает.
  Запускается **вручную** командой `/parch:janitor`.
- Ничего из этого не запускается само в CI и по расписанию.

## Что строим (три PR)

**PR 1.** Роль `reviewer` и `/parch:review`; правило «ревью до просьбы “сливай”» в `AGENTS.md` (после «утверждаю» по тексту: файл
защищён, слияние ваше). **PR 2.** Роль `janitor` и `/parch:janitor` (один кандидат за запуск, список утверждённых берёт из
репозитория). **PR 3.** Тесты приёмки: janitor не удаляет модуль с `keep-until` и неутверждённое; reviewer на заведомо плохом PR
(тест всегда проходит, но ничего не проверяет) пишет замечание, на хорошем молчит.

## Как проверим (тесты приёмки)

`tests/test_janitor.py`, `tests/test_reviewer.py`: файлы ролей не длиннее 40 строк и согласованы с охраной путей (janitor не
правит тесты); janitor отказывается удалять `keep-until`, код без утверждения и код, у которого нашлась ссылка; метка создаётся до
удаления; ревьюер не правит файлы PR. Качество ревью ИИ автоматически не доказать: его проверяет ваш выборочный просмотр первых десяти PR.

## Риски и откат

ИИ-ревью может пропустить ошибку или придраться зря: оно советчик, слияние решаете вы по-прежнему. Janitor может удалить нужное,
если поиск не видит динамический вызов: поэтому только утверждённое вами и всегда с меткой, откат одной командой по метке.
Откат блока: удалить роли и команды; репозиторий проекта не меняется.

## Что откладывается и сроки

- Откладывается: расписание janitor (запуск по расписанию и облачная рутина не обсуждаются, пока не проверена подписка);
  автослияние PR janitor (слияние только вашим «сливай»); уборка дублей и горячих точек (только мёртвый код); ревью качества
  тестов (остаётся частичной защитой); ревью в CI через платный API.
- Сроки: примерно три PR и три сессии. PR 1 идёт сразу после первого PR блока F18 (техзависимости от F14 нет), PR 2 и PR 3 после
  F14. Сдвиг F14 сдвигает только готовность блока, не начало.

## Решения владельца (2026-10-05)

1. Ревью обязательно для PR, которые сливает владелец (список выше); остальные без обязательного ревью.
2. Janitor запускается вручную; запуск по расписанию из блока убран.
