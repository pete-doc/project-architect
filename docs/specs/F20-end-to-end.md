# Спецификация F20. Сквозной прогон на новом проекте

Статус: черновик, ждёт утверждения владельца. Цель G1 («проект на любом из четырёх языков подключается одной командой,
и результат проверен на живом проекте»). Зависит от F3 (init-project), F11 (цель и Actions в init), F16 (ревью).

## Зачем

Табло показывает G1 выполненной, хотя `/parch:init-project` ни разу не запускался на настоящем проекте, шаблоны CI не
шли на GitHub, а в fm26-data на GitHub ноль запусков Actions. Тесты продукта проверяют файлы на диске, а не то, что
всё это работает вместе. F20 закрывает G1 **живым прогоном** на новом пустом проекте. Языковые критерии (TypeScript,
C#, PowerShell) сюда не входят: берём Python, самый короткий путь; остальные языки идут отдельными прогонами по
решению владельца.

## Сценарий приёмки и что видит владелец

| № | Шаг | Что должно получиться | Как вы это видите без чтения кода |
|---|---|---|---|
| 1 | Приватный репозиторий Python на GitHub (создаёт владелец, пустой, с одним файлом README) | Репозиторий есть, секретов в нём нет | Страница репозитория в браузере, значок «Private» |
| 2 | `/parch:init-project` в клоне репозитория | Созданы цель, конституция, документы, правила защиты и CI; ответы на вопросы записаны вашими словами; созданное и пропущенное названо в отчёте | Ответ команды по-русски и список новых файлов на странице коммита |
| 3 | Коммит и отправка в PR; CI на GitHub | Проверки зелёные (`ruff`, типы, `standard`, тесты) в Actions, на Ubuntu | Зелёная галочка у PR; в Actions один прогон, не десятки |
| 4 | Одна небольшая функция через `implementer` | В «Основаниях» PR записан поиск готового; у функции есть тест; CI зелёный | Раздел «Основания» в описании PR, галочка CI |
| 5 | Заведомое нарушение (например, удалённый тест или пакет не из списка) | CI красный и называет причину по-русски; без исправления слить нельзя | Красный крест у PR и текст причины в проверке |
| 6 | `/parch:review НОМЕР` | Ревью в чистом контексте оставило комментарий в PR, итог пересказан по-русски | Комментарий в PR и пересказ в чате |
| 7 | Слияние хорошего PR | Ветка `status` обновилась: `state/STATUS.md` показывает блок и цель нового проекта | Файл `state/STATUS.md` на ветке `status` открывается в браузере |

Если шаг не получился, прогон останавливается: причина записывается как проблема продукта (`docs/BACKLOG.md` или
инцидент), исправление идёт обычным блоком, а прогон повторяется с шага 1 на новом пустом репозитории. Ничего не
обходить: заблокировал hook, значит, ждём вашего ответа.

## Что нужно от владельца и когда

| Когда | Что | Зачем |
|---|---|---|
| **До старта** | Создать пустой приватный репозиторий на GitHub и дать его адрес; выбрать имя проекта и две-три фразы о нём (для вопросов init) | Репозиторий создаёт только владелец: ИИ не создаёт аккаунты и репозитории |
| **До шага 3** | Проверить бюджет GitHub Actions для приватных репозиториев (Settings → Billing): нужны минуты на несколько прогонов Ubuntu. Оценку минут исполнитель запишет в описание PR заранее (правило 10, ADR-0011) | Без бюджета Actions не стартуют, и прогон встанет на шаге 3 |
| **На шаге 2** | Утвердить цель нового проекта (init оставляет `GOAL.md` черновиком) | Без утверждённой цели планирование не начинается |
| **На шаге 5** | Подтвердить, что нарушение подложено намеренно | Чтобы красный CI не приняли за настоящую поломку |
| **В конце** | Отметить пункты в `state/acceptance/F20.md` и дать итог | Блок принимает только владелец (ADR-0014) |

## Что считается успехом и что нет

Успех: все семь шагов получились на одном репозитории подряд, а пять отметок приёмки поставлены вами. Только после этого
G1 можно считать выполненной. Не успех: «файлы создались», «тесты продукта зелёные» без прогона на GitHub.

## Табло до приёмки

F20 заведён блоком под цель G1 (`state/features.json`, статус `planned`, `passes: false`). Пока `state/acceptance/F20.md`
не принят, блок не может стать «готово», и по формуле табло G1 показывается как «4 из 5», а не «выполнен».
Записи блока для этого достаточно (проверено запуском `parch_status` на копии до и после: было «критерий G1 выполнен»,
стало «G1 — 4 из 5», F20 в строке «впереди»).

## Риски и откат

Прогон создаёт только новый приватный репозиторий: продукт и другие проекты не меняются. Откат: удалить репозиторий.
Риск расхода квоты Actions: ограничен Ubuntu и числом прогонов из таблицы выше; больше одного повторного прогона без
вашего слова не запускается.
