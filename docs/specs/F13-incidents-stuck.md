# Спецификация F13. Инциденты, бюджет блока и статус «застрял»

Статус: утверждена владельцем, 2026-10-04 (с поправками, они внесены ниже). Критерий цели: G6 («ИИ не теряет нить
проекта: петли обнаруживаются, решения и уроки не забываются»), разделы 6.3 и 6.6 стандарта.

## Зачем

Сейчас ИИ может бесконечно чинить одно и то же: исполнитель ходит по кругу в сессии, а планировщик заводит подзадачу за
подзадачей, хотя исправляемое, возможно, вовсе не нужно продукту. Цена такой петли это минуты CI, ваше внимание и
нить проекта, которая теряется. Блок решает две вещи: **петля обнаруживается и останавливается**, а **застрявший блок
доходит до вас короткой карточкой «отказаться / обойти / продолжать»**, а не бесконечной серией попыток.

## Что вы получите

- Отчёты о сбоях лежат в `state/incidents/ДАТА-БЛОК-слово.md` и обязаны отвечать на два вопроса. Первый: «что сломается
  для цели, если блок бросить» (раздел «Влияние на цель»: критерий `G…` или слова «ни один», обходной путь, сколько уже
  потрачено). Второй: «не решалась ли это раньше» (раздел «Что нашёл в истории»: прошлые инциденты, `docs/LESSONS.md`,
  коммиты и PR по тем же файлам, со ссылками или записью «искал там-то, не нашёл»).
- У блока есть бюджет инцидентов (по умолчанию 2). Достигнут бюджет, блок получает статус `stuck`, табло выносит его в
  «Нужно ваше решение» с карточкой и тремя вариантами ответа одним словом.
- Хук останавливает сессию, которая крутится: три одинаковые ошибки подряд или правка одного файла туда-обратно.

## Что строим (две отправки в двух PR)

**PR 1. Отчёты, бюджет, `stuck`, карточка.**
1. Шаблон отчёта об инциденте (`docs/INCIDENT_TEMPLATE.md`) и строка «Бюджет инцидентов на блок: 2» в шаблоне
   `CONSTITUTION.md` (init копирует).
2. Проверка `standard`: имя файла `ДАТА-БЛОК-слово.md` (`NONE` вместо блока, если работа вне блока), блок есть в
   `features.json`; раздел «Влияние на цель» не пуст и содержит `G…` или «ни один»; раздел «Что нашёл в истории» не пуст
   и содержит ссылку (адрес, PR, коммит, прошлый отчёт) или запись «искал там-то, не нашёл», пустой раздел роняет отчёт;
   блок, у которого инцидентов не меньше бюджета, обязан иметь статус `stuck` (его ставит тот же PR, что добавляет
   отчёт). Это сегодняшняя проверка «blocked без отчёта» плюс новые.
3. Табло: счёт инцидентов остаётся производным (ADR-0012, в `main` не пишется); блок `stuck` показывается карточкой в
   «Нужно ваше решение»: для какого критерия нужен, обходной путь из отчёта, три варианта.
4. Снять `stuck` может только ваше решение: PR с изменением `status` или с полем блока `incident_budget` (+1) и вашим
   «сливай»; бюджет блока поднимается не молча, а записью в отчёте.
5. Правило в `AGENTS.md`: имя ветки начинай с идентификатора блока (`F13-…`), если работа относится к блоку.

**PR 2. Обнаружение петель.** В журнале аудита (`.claude/audit/`) считаются «подпись» ошибки (проверка + файл + текст) и
правки туда-обратно. Петля останавливает сессию всегда: блок сессия определяет по префиксу ветки; без префикса петля
всё равно останавливает, а отчёт называет блок вручную или «вне блока» (`NONE`). После петли хук блокирует правки кода
и разрешает только запись отчёта в `state/incidents/`. **Когда отчёт записан, правки кода в этой сессии остаются
запрещены и сессия завершается; продолжение только новой сессией** (чистый контекст, без старого журнала).

## Чего не строим

Автоматическую запись `stuck` в `main` с CI (ADR-0012: CI в `main` не пишет); запуск «новой сессии с чистым контекстом»
(это действие владельца или планировщика); анализ истории git на повторные дефекты (отдельно, F16); платный API.

## Как проверим (тесты приёмки)

Для каждого правила есть заведомо плохой пример, который проверка обязана остановить: отчёт без «Влияния на цель», с
формальным разделом без `G…` и без «ни один», с пустым разделом «Что нашёл в истории» (нет раздела, пустой, только
метки шаблона, ссылка спрятана в комментарий, слова без ссылки), неподготовленный шаблон, неверное имя, несуществующий
блок; блок с исчерпанным бюджетом, но не `stuck`. PR 2: три одинаковые подписи подряд останавливают, две нет; правка
туда-обратно останавливает; без префикса ветки сессия всё равно останавливается; после петли запись отчёта проходит,
правка кода нет, в том числе после записи отчёта. На табло: карточка `stuck` содержит три варианта, критерий цели и
обходной путь. Тесты приёмки блока: `tests/test_incidents.py` (PR 1) и `tests/test_loop_guard.py` (PR 2).

## Решения владельца (2026-10-04)

1. Бюджет по умолчанию 2 инцидента на блок: да.
2. Статус `stuck` ставит PR с последним отчётом (проверка требует), а не CI: да (ADR-0012).
3. Префикс ветки `F13-…`: да; без префикса петля всё равно останавливает сессию, блок называется вручную или «вне блока».
4. После петли и отчёта правки кода в этой сессии запрещены, сессия завершается: да, продолжение новой сессией.
5. Обязательный раздел отчёта «Что нашёл в истории», пустой роняет `standard`: да, с тестом.

## Риски

Слишком чуткий детектор петель даёт ложные остановки; поэтому порог 3, как в стандарте, и остановка снимается
записью отчёта и новой сессией. Если решение окажется ошибкой, откат: убрать проверку из `standard` и хук из
`hooks.json`; отчёты и табло останутся.
