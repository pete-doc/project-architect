# ADR-0002. Hooks и скрипты на Python ради macOS и Windows

- Статус: proposed
- Тип решения: необратимое (на этом языке будут написаны все проверки фазы B)
- Дата: 2026-10-02

## Контекст

Владелец работает на macOS и на Windows 11. Bash-скрипты на Windows работают только через Git Bash,
PowerShell на macOS не установлен по умолчанию. Hooks Claude Code запускают любую команду и читают JSON со stdin.

## Решение

- Все hooks и служебные скрипты продукта пишутся на Python 3.12+ (только стандартная библиотека там, где это возможно), пути только через `pathlib`.
- Hook подключается в `plugin/hooks/hooks.json` в форме без оболочки: `"command": "python"`, `"args": ["${CLAUDE_PLUGIN_ROOT}/hooks/<имя>.py"]`. Так пробелы в путях и разница между оболочками не влияют на запуск.
- Качество самого кода продукта: ruff, pyright (strict), pytest; всё это работает в CI на Ubuntu и Windows.

## Открытый риск

На macOS команда может называться `python3`, а `python` отсутствовать; на Windows `python` может оказаться заглушкой Microsoft Store.
Способ запуска будет проверен и при необходимости уточнён в фазе B вместе с тестами на обеих системах.

## Последствия для владельца

- Что изменится: на компьютере должен быть установлен Python 3.12 или новее. Без него защитные проверки не запустятся.
- Если решение окажется ошибкой: при отсутствии Python hooks молча не сработают, поэтому в фазе B добавится проверка «Python найден» при старте сессии.
- Как откатить: переписать скрипты на другой язык; формат hooks от этого не меняется, потому что Claude Code запускает любую команду.

## Рассмотренные альтернативы

- Bash: не работает на Windows без Git Bash.
- PowerShell: нет на macOS по умолчанию.
- Node.js: он уже нужен для pyright, но целевые проекты на Python и C# не должны зависеть от него.
