# ADR-0021. Файлы долга catalog-baseline.json и modules-baseline.json защищены как standard-baseline.json

- Статус: accepted (утверждено владельцем, 2026-10-06)
- Тип решения: обратимое
- Дата: 2026-10-06

## Контекст

Проверки `catalog` (описания публичных функций, F15) и `modules` (модули без блока, F18) ведут существующие нарушения через файлы
долга `state/catalog-baseline.json` и `state/modules-baseline.json`: записанное допускается, число только снижается, новое падает.
Если агент может дописать ключ в такой файл, он отключает проверку для своего же нарушения. `state/baseline.json` и (ADR-0019)
`state/standard-baseline.json` от этого защищены охраной путей и правилом слияния, эти два файла долга оставались без защиты
(строка в `docs/BACKLOG.md` от 2026-10-05). Владелец решил защитить их так же (2026-10-06).

## Решение

`state/catalog-baseline.json` и `state/modules-baseline.json` защищены так же, как `state/standard-baseline.json` (ADR-0019):

1. Охрана путей (`plugin/hooks/guard_paths.py`, список `_STATE_FILES`) и шаблон `plugin/templates/claude/settings.json` просят
   подтверждение владельца на запись и правку файла для любой роли.
2. Любой PR, который меняет такой файл, сливает только владелец: файлы названы в условии 3 слияния PR в `AGENTS.md`
   (дополняет ADR-0003 и ADR-0019). В описании такого PR перечислены добавленные в долг ключи.
3. Тесты с плохими примерами: попытка агента записать в файл (Write, Edit, оболочка) блокируется
   (`tests/test_standard_composition.py`).

Запись долга владельцем идёт прежней командой (`catalog --update --accept-new`, `modules --update --accept-new`), её охрана путей
не блокирует: она не пишет файл через Write, Edit или перенаправление оболочки.

Остаточный риск (так же у ADR-0019): охрана путей ловит запись через Write, Edit и перенаправление оболочки, но не запуск самой команды
`parch_ci.py modules --update --accept-new` (или `catalog`, `standard`) агентом: файл пишет Python-процесс. Защита держится на правиле
слияния (условие 3) и на списке добавленных ключей в описании PR, который проверяет владелец. Отдельное решение: просить подтверждение
владельца на команду, где вместе стоят `--update` и `--accept-new` (`docs/BACKLOG.md`); владелец отклонил это предложение
2026-10-06, риск принят.

## Последствия для владельца

- Что изменится: запись в эти долги идёт только вашей командой и вашим слиянием PR; агент присылает PR, в описании которого список
  добавленных ключей.
- Если решение окажется ошибкой: лишнее подтверждение при законной записи долга; нарушений проверок это не создаёт.
- Как откатить: убрать файлы из `_STATE_FILES`, из шаблона `settings.json` и из условия 3 в `AGENTS.md`.

## Рассмотренные альтернативы

- Не защищать: агент мог бы дописать ключ в долг и отключить проверку для своего нарушения.
- Защитить в одном списке с `baseline.json` под общим ADR: ADR-0019 принят и не правится, поэтому отдельная запись.
