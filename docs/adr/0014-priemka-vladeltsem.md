# ADR-0014. Приёмка владельцем для блоков, которые не проверяются тестами

- Статус: accepted (по поручению владельца, 2026-10-03)
- Тип решения: обратимое (правило табло и формат одного файла)
- Дата: 2026-10-03

## Контекст

«Готово» на табло ставит отчёт тестов: тесты приёмки блока прошли (ADR-0012). Есть блоки, которые тестами не проверить:
пилот на реальном проекте, понятность отчёта, живая проверка на компьютере владельца. Для них агенту нельзя дать самому
поставить «готово», а владельцу нужен простой способ принять работу.

## Решение

1. У такого блока есть файл `state/acceptance/<id блока>.md` с критериями приёмки (`- [ ] критерий`) и строкой итога.
2. Блок становится «готово» на табло только когда **все критерии отмечены `[x]`** и в файле есть строка
   `Итог: принято владельцем, ГГГГ-ММ-ДД`, а файл слит в `main`. Пока этого нет, блок показан как «ждёт владельца» и
   выведен в «Нужно ваше решение» с путём к файлу.
3. Если у блока есть и тесты приёмки, и файл приёмки, нужны оба: тесты прошли и владелец принял.
4. Слияние PR, который меняет `state/acceptance/`, требует вашего «сливай» (добавлено в условия ADR-0003 в `AGENTS.md`):
   агент не может принять свою работу сам. Строку «принято владельцем» пишет владелец или агент с вашим явным «принимаю»
   в чате, и это видно в PR.
5. Пример: `state/acceptance/F17.md` (приёмка пилота на CHEAT_FIFA).

## Последствия для владельца

- Что изменится: блок без тестов нельзя закрыть без вашей отметки; на табло такие блоки видны в «Нужно ваше решение».
- Если ошибка в решении: блок остаётся «ждёт владельца», работа не пропадает.
- Как откатить: удалить файл приёмки блока; правило табло можно отключить, убрав чтение `state/acceptance/`.

## Известные границы

Слово «принято» в файле может написать и агент; защита только процессная (условие слияния ADR-0003 и ваше «сливай»).
Технической защиты файла нет: новых проверок до пилота по вашему решению не добавляется.
