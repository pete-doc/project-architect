# ADR-0017. До двух параллельных PR, если они не пересекаются по файлам

- Статус: accepted (по поручению владельца, 2026-10-04)
- Тип решения: обратимое (одно правило в `AGENTS.md`)
- Дата: 2026-10-04

## Контекст

Правило 11 разрешало один открытый PR: так PR не устаревали после чужого слияния и не конфликтовали в
`state/baseline.json`. Работа идёт последовательно, и ограничением стали не проверки, а ожидание: каждый блок ждёт слияния
предыдущего. Блоки F14 и F18 почти не пересекаются по файлам, и их можно вести двумя сессиями Claude Code одновременно.

## Решение

1. Открыто не более двух PR, и только если они не меняют одни и те же файлы. Исключения: `state/baseline.json` и
   `docs/BACKLOG.md`: их пересчитывают по очереди.
2. Каждая сессия работает в своей рабочей папке (worktree) и в своей ветке от `main`.
3. Сливаются PR строго по очереди. После слияния первого второй делает `rebase` от `main`, заново пересчитывает baseline
   и только потом идёт в слияние. Полный прогон для нового коммита запрашивается заново (ADR-0013).
4. Все остальные проверки не меняются: `preflight`, `check`, `full-run`, условия слияния ADR-0003, «сливай» владельца.
5. Параллельно допускаются только сессии Claude Code: защита (hooks) работает только в нём. Другие инструменты (Cursor)
   не подключаются: у них нет hooks, и правило 9 держалось бы на честном слове.

## Последствия для владельца

- Что изменится: два потока работы и два потока отчётов вместо одного; ускорение примерно в полтора раза, не вдвое.
- Если ошибка в решении: вероятны конфликты в `baseline.json` и лишние циклы CI; сломанный `main` невозможен, потому что
  слияние по-прежнему требует зелёных `check` и `full-run`.
- Как остановить: напишите сессии «стоп, жди»; как откатить: вернуть прежний текст пункта 11 в `AGENTS.md`.

## Известные границы

Пересечение файлов проверяет сам агент и вы при чтении отчётов; автоматической проверки нет. Если две сессии начали
править один файл, вторая останавливается и сообщает владельцу.
