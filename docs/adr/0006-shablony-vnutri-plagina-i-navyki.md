# ADR-0006. Шаблоны лежат внутри плагина; устройство навыков init-project, adr и doctor

- Статус: accepted (утверждено владельцем 2026-10-02)
- Тип решения: необратимое (меняет структуру репозитория и то, что получает каждый проект при подключении)
- Дата: 2026-10-02

## Контекст

Фаза C добавляет шаблоны документов, CI и состояния, навыки `/parch:init-project` и `/parch:adr`, а по
решению владельца ещё и `/parch:doctor`. При чтении документации Claude Code обнаружилось расхождение с BUILD_PLAN.md:
плагин при установке видит только свою папку (`plugin/`), пути за её пределы запрещены («path escapes plugin
directory»). План же клал `templates/` рядом с `plugin/`, и после установки навык не нашёл бы шаблоны.

## Решение

1. **Шаблоны перенесены в `plugin/templates/`** (`docs/`, `ci/`, `state/`, `claude/`). Раздел 3 плана и ADR-0001
   этим уточняются: плагин и шаблоны по-прежнему один продукт, но шаблоны теперь внутри плагина.
2. **Навыки.** Каждый навык состоит из `SKILL.md` (инструкция агенту по-русски) и скрипта на Python, который делает
   всю механическую работу: создаёт файлы, нумерует ADR, готовит проверку. Агент задаёт вопросы владельцу и пишет
   тексты, а файлы создаёт скрипт: так результат одинаков и проверяется тестами. Скрипты запускаются через тот же
   запускающий файл `run-hook.cmd` (ADR-0005), данные передаются JSON-ом через stdin (так не ломают кавычки и русские
   символы в команде).
3. **`/parch:init-project`**: задаёт 3–5 вопросов, затем скрипт ничего не перезаписывает (существующие файлы
   пропускает и сообщает), добавляет правила permissions в `.claude/settings.json` слиянием, пополняет `.gitignore`,
   а `CONSTITUTION.md` создаёт **последним**, потому что его появление включает защитные hooks.
   CI-шаблон пока есть только для Python (ruff, pyright, pytest). Для TypeScript, C# и PowerShell в `CONSTITUTION.md`
   записывается стек, пакеты и пояснение, а CI появится в фазе D вместе с проверками языка. Выдавать «зелёный» CI-шаблон
   без реальных проверок я не стал: ложная зелень хуже честного «пока нет».
4. **`/parch:adr`**: решает, обратимое решение или нет (критерии в `SKILL.md`); скрипт создаёт запись из шаблона
   (для необратимого с разделом «Объяснение для владельца на одну страницу»), нумерует и пересобирает индекс
   `docs/adr/README.md`. Статус новой записи всегда `proposed`.
5. **`/parch:doctor`** (**вне плана**, по решению владельца): в живой сессии создаёт временный проект с `CONSTITUTION.md`,
   пробует три безобидных запрещённых действия (`rm -rf` пустой временной папки, новый `.md` вне `docs/`, установка пакета
   не из списка), смотрит, остановили ли их именно hooks (по метке `[guard_...]` в ответе), и сообщает владельцу по-русски,
   работает ли защита и почему нет. Это единственная проверка, которая показывает, что Claude Code на данном компьютере
   действительно запускает hooks. Проба удаления безопасна: если защита не сработает, пропадёт пустая временная папка.
6. **Hooks определяют проект по месту действия, а не только по папке сессии.** Корень проекта берётся от текущей папки
   вызова и от пути файла (ближайшая папка с `CONSTITUTION.md`), с запасным вариантом на папку сессии. Это нужно для
   `/parch:doctor` (временный проект лежит вне проекта сессии), а также для рабочих копий git и вложенных проектов.
   Вложенный проект защиту внешнего не ослабляет: проверяются оба корня. Относительные пути считаются от текущей папки.
7. **Перевод ADR в `accepted` стал действием владельца.** Раньше агент мог открыть свой ADR со статусом `proposed`
   и просто переписать статус на `accepted`. Теперь правка, которая ставит такой статус (в том числе создание уже
   принятой записи и правка через оболочку), требует подтверждения владельца так же, как другие защищённые пути.

## Последствия для владельца

- Что изменится: после установки плагина команды `/parch:init-project`, `/parch:adr` и `/parch:doctor` работают из коробки;
  проект подключается одним разговором из 3–5 вопросов. Агенты больше не смогут сами утвердить своё решение.
- Если решение окажется ошибкой: структура шаблонов и формат `CONSTITUTION.md` (разделы «Разрешённые пакеты» и «Команды
  проверки») закрепятся в подключённых проектах; менять их потом придётся в каждом проекте. Пока подключённых проектов нет,
  отмена дешёвая; после пилота дорожает.
- Как откатить: вернуть `templates/` в корень и поправить пути в скриптах (но тогда установленный плагин перестанет
  находить шаблоны); навыки отключаются удалением папок `plugin/skills/<имя>/`.

## Ограничения

- `/parch:init-project` и `/parch:adr` проверены тестами на скриптах и на сгенерированном Python-проекте (его CI-команды
  проходят). В живой сессии Claude Code навыки не запускались: сессия в этой среде не авторизована. Это проверит
  `/parch:doctor` (для защиты) и первое реальное использование.
- CI для TypeScript, C# и PowerShell не создаётся до фазы D.

## Рассмотренные альтернативы

- Сделать корнем плагина весь репозиторий: в установленный плагин попали бы тесты, документы и всё остальное.
- Копировать шаблоны в `plugin/` сборочным шагом: два экземпляра одних и тех же файлов, расхождение неизбежно.
- Пусть агент создаёт файлы сам по описанию: результат разный от раза к разу и не проверяется тестами.
