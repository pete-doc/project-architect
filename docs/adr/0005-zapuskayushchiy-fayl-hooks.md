# ADR-0005. Запускающий файл hooks сам находит Python

- Статус: proposed
- Тип решения: необратимое (меняет, как запускаются все hooks; заменяет пункт о запуске из ADR-0002)
- Дата: 2026-10-02

## Контекст

ADR-0002 запускал hooks командой `python`. Это зависит от того, как Python установлен на конкретном
компьютере: на Mac он часто называется только `python3` или подключается через настройку терминала (Anaconda),
на Windows `python3` и `python` могут оказаться заглушками Microsoft Store, а рабочий Python доступен только
как `py -3`. Если команда не нашлась, hook не блокирует действие, а лишь пишет ошибку (блокирует только код
выхода 2), то есть защита молча отключается. Владелец не будет проверять Mac, поэтому решение не должно
зависеть от такой проверки.

## Решение

Один файл `plugin/hooks/run-hook.cmd`, который одновременно является скриптом для `sh` (macOS, Linux,
Git Bash на Windows) и пакетным файлом Windows: `sh` пропускает блок до метки `CMDBLOCK`, `cmd` пропускает
первую строку. Он:

1. перебирает кандидатов в порядке `python3`, `python`, `py -3`;
2. каждого проверяет по-настоящему, запуская `-c` с проверкой версии (нужен Python 3.12 или новее), поэтому
   заглушки Microsoft Store (ответ «Python не найден», код 9009) и слишком старые версии пропускаются;
3. запускает нужный скрипт из своей папки, передаёт ему stdin и возвращает его код выхода и вывод как есть;
4. если подходящего Python нет, в проекте с `CONSTITUTION.md` (то есть подключённом к ProjectArchitect) выдаёт понятное
   сообщение на русском: для охранных hooks (`guard_*`) блокирует действие (код 2), для остальных пишет ошибку
   (код 1); в посторонних проектах молчит и ничего не блокирует.

В `plugin/hooks/hooks.json` каждая команда имеет вид `sh "${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.cmd" имя_скрипта.py`
(форма с оболочкой). Файл хранится с переводами строк LF (`.gitattributes`), на него выставлен бит запуска.
Вызов через `sh` не зависит от бита запуска.
Файл целиком состоит из ASCII-символов: `cmd` при включённой кодовой странице UTF-8 неверно разбирает любые
остальные байты, и первый вариант файла с русскими комментариями упал в CI на Windows. Поэтому русское сообщение
«Python не найден» для `sh` записано в файле кодами (`printf` с восьмеричными escape-последовательностями), а
сообщение для `cmd` на Windows выдаётся по-английски.

## Что проверено, чего нет

- Тесты подменяют установку Python заглушками в начале PATH: только `python3`; сломанный `python3` (как у Store) и рабочий
  `python`; только `py`; слишком старый Python; папка плагина с пробелами в пути; вывод и код выхода hook доходят без
  искажений; Python нет вообще (охранный hook блокирует, остальные не блокируют, в чужом проекте тишина).
  Всё это гоняется через `sh` на macOS, Linux и Windows, а путь через `cmd` дополнительно на Windows.
- Не проверено: запуск живым Claude Code (сессия не авторизована) и реальная машина владельца с Mac.

## Ограничение

Windows **без** Git Bash: Claude Code тогда запускает команды через PowerShell, где нет `sh`, и hooks выдадут
ошибку «команда не найдена» (действие при этом не блокируется). Нужен Git for Windows (он обычно уже стоит).
На компьютере владельца Git Bash есть. Если понадобится поддержать Windows без Git Bash, потребуется второй
запускающий файл для PowerShell.

## Последствия для владельца

- Что изменится: hooks работают независимо от того, как поставлен Python (`python3`, `python`, `py -3`, Anaconda,
  Microsoft Store). Нужен Python 3.12 или новее, а на Windows ещё и Git for Windows.
- Если решение окажется ошибкой: при проблеме с запуском вы увидите сообщение «Не найден Python 3.12 или новее» (в
  подключённых проектах) вместо тихого отключения защиты. Худший случай: охранные hooks заблокируют работу, пока
  не будет установлен Python; обойти можно командой `claude plugin disable parch@project-architect`.
- Как откатить: вернуть в `hooks.json` команды `python` с `args` (форма из ADR-0002) и удалить `run-hook.cmd`.

## Рассмотренные альтернативы

- Команда `python` напрямую (ADR-0002): зависит от установки Python, при ошибке молча отключает защиту.
- Ссылка `python` → `python3` у владельца на компьютере: чинит один компьютер, а не продукт.
- Два набора hooks, по одному на оболочку: на Windows с Git Bash сработали бы оба набора, и всё выполнялось бы дважды.
