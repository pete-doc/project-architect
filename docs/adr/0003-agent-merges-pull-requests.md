# ADR-0003. Слияние pull request выполняет агент по строгим условиям

- Статус: accepted (решение владельца, 2026-10-02)
- Изменено 2026-10-02 по решению владельца: в условие 3 добавлены `plugin/agents/`, `plugin/templates/ci/`, `requirements-dev.txt`; включено автоудаление веток после слияния.
- Изменено 2026-10-03 по решению владельца: в условие 3 добавлен `state/baseline.json` (baseline «храповика» продукта).
- Тип решения: обратимое (настройка репозитория и правило в `AGENTS.md`), но влияет на безопасность процесса

## Контекст

Прямой пуш в `main` закрыт правилом репозитория: изменения идут только через pull request (PR) с зелёным CI.
Владелец не читает код, поэтому ручное слияние каждого PR превращается в формальность без реальной проверки.
При этом часть PR (CI, настройки Claude, hooks, тесты, правила в `AGENTS.md`) меняет сами механизмы контроля, и такие изменения агент одобрять не должен.

## Решение

Агент сам сливает PR способом Squash and merge через автослияние GitHub (`gh pr merge --auto --squash`), только если выполнены все условия:

1. Все обязательные проверки CI зелёные.
2. В PR нет ADR со статусом `proposed`.
3. PR не меняет `.github/`, `.claude/`, `plugin/hooks/`, `plugin/agents/`, `plugin/templates/ci/`, `tests/` (кроме добавления новых тестов), `AGENTS.md`, `CLAUDE.md`, `requirements-dev.txt`, `state/baseline.json`, `pyproject.toml` в части правил проверок.
4. Описание PR заполнено по правилу 7 (три раздела на русском, с выводом тестов).

Если не выполнено хотя бы одно из условий 2–4, агент не сливает и пишет владельцу в чат одной строкой, что именно требует его решения. Слияние выполняется только после ответа «сливай».
Условие 1 обеспечивает сам GitHub: автослияние не сработает, пока обязательные проверки не зелёные.

Настройки репозитория: включено Allow auto-merge; из способов слияния оставлен только Squash; ветки после слияния удаляются автоматически.

## Исключение для PR #1

В PR #1 меняются CI и `AGENTS.md`, то есть условие 3 не выполнено. Владелец явно одобрил это слияние и утвердил ADR-0001 и ADR-0002 (статус `accepted`). Исключение действует только для PR #1 и не переносится на другие PR.

## Последствия для владельца

- Что изменится: обычные безопасные PR (новый код, документы, новые тесты) сливаются без вашего участия. Всё, что трогает защитные механизмы, ждёт вашего слова.
- Если решение окажется ошибкой: агент сможет слить код с ошибкой, которую не заметили тесты. Защита: условие 1 (CI), условие 3 (агент не может ослабить проверки сам) и история `main` в один коммит на PR.
- Как откатить: выключить Allow auto-merge в настройках репозитория или удалить правило из `AGENTS.md`; ошибочное слияние отменяется командой `git revert` на коммит этого PR.

## Рассмотренные альтернативы

- Владелец сливает все PR вручную: надёжно по форме, но проверки он не читает, а процесс замедляется.
- Агент сливает любые PR при зелёном CI: агент мог бы ослабить сами проверки и сам себя одобрить.
