# ADR-0015. Каталог возможностей и описания функций проверяет parch_ci, а не линтер языка

- Статус: accepted
- Тип решения: обратимое (одна проверка CI и один генерируемый файл)
- Дата: 2026-10-04

## Контекст

Главная причина хаоса в ИИ-разработке: ИИ пишет новое, не зная, что уже есть. Спецификация F15 требует каталог
возможностей, который собирается из однострочных описаний публичных функций, и обязательные описания (публичная
функция без описания не проходит). Описания можно проверять правилами линтера (ruff `D102` и `D103`, предупреждение
компилятора C# `CS1591`), но линтер не соберёт каталог и не проверит, что каталог не отстал от кода. Правила линтера
меняют настройки проекта (проверка `settings` следит за ними), а `CS1591` сейчас отключён в шаблоне C#.

## Решение

1. Новая проверка CI `parch_ci.py catalog` (код в `parch_catalog.py` рядом): публичная функция без однострочного
   описания, описание длиннее 120 знаков или каталог, не совпадающий с кодом, останавливают CI.
2. Каталог лежит в `docs/CAPABILITIES.md`, собирается командой `catalog --update`, руками не правится.
3. Описание: Python первая строка docstring, C# первая строка `<summary>`. Публичная функция: Python имя без `_`
   (функция модуля и метод публичного класса), C# `public` метод публичного типа; `inheritdoc` считается описанием.
   Тесты, сборочные и служебные папки не входят.
4. Языки по очереди: Python и C# в PR 3, TypeScript и PowerShell следующим шагом.

## Последствия для владельца

- Что изменится: в проектах по стандарту новая публичная функция без строки описания не пройдёт CI; каталог видно в
  `docs/CAPABILITIES.md`, ИИ-исполнитель ищет в нём готовое перед новым кодом (протокол в PR 4).
- Что будет при ошибке: разбор по тексту приблизительный (C# разбирается регулярными выражениями, не компилятором),
  возможны ложные находки; CI называет файл и строку, правка занимает одну строку описания.
- Как откатить: убрать шаг `catalog` из `python.yml` и `csharp.yml` и удалить `docs/CAPABILITIES.md`.
