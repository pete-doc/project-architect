# ADR-0019. Файл долга state/standard-baseline.json защищён как state/baseline.json

- Статус: accepted (утверждено владельцем, 2026-10-06)
- Тип решения: обратимое
- Дата: 2026-10-05

## Контекст

В F14 (PR 1 и 2) проверка `standard` на существующих проектах ведёт нарушения состава проекта и исторические отчёты об
инцидентах через файл долга `state/standard-baseline.json`: записанное допускается, число только снижается, новое падает.
Если агент может дописать в этот файл ключ (например `incident:<новый отчёт>`), он отключает проверку для своего же
нарушения. `state/baseline.json` (храповик тестов) от этого защищён охраной путей и правилом слияния (ADR-0003), файл
долга до сих пор не был. Владелец потребовал защитить его так же (2026-10-05, утверждение спецификации F14).

## Решение

`state/standard-baseline.json` защищён так же, как `state/baseline.json`:

1. Охрана путей (`plugin/hooks/guard_paths.py`, список `_STATE_FILES`) и шаблон `plugin/templates/claude/settings.json`
   просят подтверждение владельца на запись и правку файла для любой роли.
2. Любой PR, который меняет этот файл, сливает только владелец: файл добавлен в условие 3 слияния PR в `AGENTS.md`
   (дополняет ADR-0003, как ADR-0014 дополнил его для `state/acceptance/`).
3. В описании такого PR перечислены добавленные в долг ключи (так владелец видит, какой долг он принимает).
4. Тесты с плохими примерами: попытка агента записать в файл (Write, Edit, оболочка) блокируется
   (`tests/test_standard_composition.py`).

Ограничение: ключ `incident:<имя файла>` покрывает отчёт целиком. Пока отчёт записан в долг, в нём не проверяются ни
имя, ни блок, ни разделы, в том числе новые нарушения, которые в него дописали (так задано спецификацией F14, пункт 3).
Ключ цикла зависимостей строится от состава цикла, поэтому второй цикл в долг не попадает молча.

## Последствия для владельца

- Что изменится: запись в долг идёт только вашей командой `standard --update --accept-new` и вашим слиянием PR; агент
  присылает PR, в описании которого список добавленных ключей.
- Если решение окажется ошибкой: лишнее подтверждение при законной записи долга; нарушений проверки это не создаёт.
- Как откатить: убрать файл из `_STATE_FILES`, из шаблона `settings.json` и из условия 3 в `AGENTS.md`.

## Рассмотренные альтернативы

- Не защищать, полагаясь на ревью: агент мог бы дописать ключ в долг, и проверка перестала бы ловить его нарушение;
  ревью не гарантия.
- Защитить заодно `state/catalog-baseline.json` и `state/modules-baseline.json` (те же свойства): вне заявленного
  объёма PR, записано в `docs/BACKLOG.md` предложением для решения владельца.
