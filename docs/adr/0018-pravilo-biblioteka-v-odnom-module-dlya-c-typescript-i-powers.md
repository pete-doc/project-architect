# ADR-0018. Правило «библиотека в одном модуле» для C#, TypeScript и PowerShell проверяет parch_ci по тексту

- Статус: accepted (обратимое, правило 6 `AGENTS.md`)
- Тип решения: обратимое
- Дата: 2026-10-05

## Контекст

Спецификация F15 требует правило архитектуры «низкоуровневую библиотеку подключать только в одном модуле». Для Python оно
сделано средствами import-linter (PR 4). Для C#, TypeScript и PowerShell владелец поручил сделать отдельным шагом. Родные
инструменты неудобны: у PowerShell нет проверки архитектуры вовсе (ADR-0010, тонкий «клей»); ArchUnitNET видит библиотеку
из чужой сборки только если загрузить её в анализ; dependency-cruiser требует Node в проекте, где его может не быть.

## Решение

1. Новая проверка CI `parch_ci.py libraries --language ЯЗЫК` (код в `parch_libraries.py` рядом с `parch_ci.py`).
2. Правила лежат в `state/architecture.json` (меняет только владелец, как остальные файлы проверок):
   `{"library": "System.Data", "language": "csharp", "only_in": ["src/Shop/Db"]}`.
3. Что считается подключением: C# `using`; TypeScript `import`, `require`, `import()`; PowerShell `Import-Module`,
   `using module`, `#Requires -Modules`, `Add-Type -AssemblyName`. Подмодуль библиотеки тоже подключение (`System.Data.Common`,
   `fs/promises`). Комментарии, тесты и сборочные папки не считаются.
4. Подключение вне `only_in` провал с файлом и строкой. Правило с несуществующим путём `only_in` провал (опечатка не должна
   давать «пусто-зелёное» правило). Нет файла правил: правил нет, проверка проходит.
5. Python остаётся на import-linter (контракт `forbidden` с `ignore_imports`).

## Последствия для владельца

- Что изменится: для проектов на C#, TypeScript и PowerShell вы (через `state/architecture.json`) называете библиотеки и модуль,
  которому они разрешены; ИИ не сможет подключить их ещё где-то, CI покажет файл и строку.
- Если решение окажется ошибкой: поиск по тексту может не заметить необычное подключение (например, через алиас пакета) или
  принять за подключение лишнее; правило не заменяет проверку уровней, которую дают родные инструменты.
- Как откатить: убрать шаг `libraries` из шаблонов CI и файл `state/architecture.json`; код проекта не меняется.

## Рассмотренные альтернативы

- ArchUnitNET для C# и dependency-cruiser для TypeScript: точнее, но тяжелее, не покрывают PowerShell и требуют отдельных
  настроек и сред в каждом проекте.
- Banned API analyzers для C#: новый пакет (отдельный ADR), правило на уровне проекта, а не модуля.
