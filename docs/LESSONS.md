# LESSONS — неочевидные уроки продукта

> До 50 строк. Каждый урок: что было неочевидно, и ссылка на регрессионный тест.

- Цепочка команд (`;`, перевод строки) не останавливается на упавшем тесте: 2026-10-03 baseline записали по прогону с 10 ошибками. Теперь `baseline --update` отказывается писать запуск с упавшими тестами. Тест: `tests/test_product_ratchet.py::test_baseline_refuses_a_run_with_failed_tests`.
- Зелёный прогон на `main` значит «табло собрано», а не «тесты прошли»: в задании `state` pytest идёт с `|| true`, о тестах судит только `check` на PR. 2026-10-10 табло показало «Упавших: 1» и «Нужно ваше решение: ничего». Теперь упавшие тесты выводятся в «Нужно ваше решение» (до 10, остальные — ссылкой на раздел «Тесты»). Тест: `tests/test_status.py::test_a_failed_test_is_put_in_front_of_the_owner`.

## Журнал процессных ошибок ИИ

Строка = ошибка и счётчик повторов. На втором повторе обязательна автоматика (скрипт, hook, проверка): запись
удаляется из журнала, а в раздел «Закрыто автоматикой» ставится ссылка на неё. Ошибки процесса (не кода) вносит
агент сам, когда замечает повтор.

| Ошибка | Повторов | Последний раз | Автоматика |
|---|---|---|---|
| Обход блокировки hook другим путём (временная папка вместо удаления) | 1 | 2026-10-03 | правило 9 в `AGENTS.md`; на втором повторе нужна проверка |
| Правило ссылалось на роль, которой нет в плагине (охрана путей пускала к тестам только architect и tester, агентов не было): тест не мог написать никто, нашёл только живой прогон F20 (шаг 4), не тесты и не ревью | 1 | 2026-10-07 | `tests/test_roles.py` (каждая роль в hooks, шаблонах, навыках и STANDARD.md есть в `plugin/agents/` или помечена в BACKLOG) |
| Правило «разрешено только своё» построено на оценке, написанной для обратной задачи («запрещены только защищённые пути»): лишнее слово там безвредно, здесь даёт ложный блок (`git checkout`, отчёт в файл), а предикат шире намерения (суффикс папки, маска имени). Две проходки ревью PR 72 нашли то, что должна была найти таблица плохих и хороших примеров до отправки. **Правило:** правило-allowlist проверяется таблицей обычных команд роли (должны проходить) и граничных плохих примеров, а изменение общей охраны ещё и тестом «другие роли не изменились» | 1 | 2026-10-07 | `tests/test_roles.py::test_tester_shell_commands_are_blocked_only_when_they_write_outside_the_tests`; на втором повторе: проверка таблицы для каждой роли с allowlist |
| Навык, запускающий внешние инструменты, слит без живого прогона: восемь ошибок нашлись только прогоном на пилоте после слияния. **Правило:** PR навыка, запускающего внешние инструменты, проходит живой прогон на пилоте до слияния, итог прогона записан в описании PR | 1 | 2026-10-04 | правило; на втором повторе: пункт «живой прогон» в шаблоне PR и проверка |

## Закрыто автоматикой

- Тест проходит локально и падает в CI (3 повтора: импорт `tests.…` на Linux, 2026-10-03; BASH_ENV и PATH CircleCI ставят
  настоящие dotnet и node впереди подставных команд теста, 2026-10-06, PR 68; `python -m pytest` вместо `pytest`
  скрыл `No module named 'src'`, 2026-10-07, прогон F20) → автофикстура `no_ci_bash_env` в `tests/conftest.py`
  (BASH_ENV не виден ни одному тесту), тест
  `tests/test_parch_state.py::test_a_ci_bash_env_never_reaches_the_shell_tests` (запускает тесты шагов под BASH_ENV
  в стиле CI); команды проверок из CONSTITUTION (список `init`) обязаны запускаться так же, как в шаблонах CircleCI:
  `tests/test_command_parity.py::test_check_commands_in_the_constitution_run_the_same_way_as_in_ci` (плохой пример:
  `tests/test_command_parity.py::test_pytest_through_python_m_is_a_mismatch_with_plain_pytest_in_ci`), шлюз Stop
  запускает `pytest -q` и ловит ошибку импорта: `tests/test_flow.py::test_stop_gate_catches_an_import_error_that_python_m_pytest_hid`.
  Импорты на Linux по-прежнему ловит только CI.

- Версия плагина не поднята после правок `plugin/` (у владельца остался 0.1.6, а в `main` ушло 11 файлов, около 760
  строк) → `scripts/release_check.py` (сверка с тегом `v*`, `--strict` для PR «выпуск»), сообщение в `preflight.py`,
  тест `tests/test_release_check.py::test_the_same_drift_fails_in_strict_mode_which_the_release_pr_uses`.

- Отправка в CI без локальной проверки (ruff, формат, импорт, полный прогон): красные и холостые прогоны, около 11
  повторов за 3–4 октября → `scripts/preflight.py` (одна команда, остановка на первой ошибке), тест
  `tests/test_preflight.py`.
- Удаление и переименование тестов без решения владельца (3 повтора) → храповик `parch_ci.py tests`, тест
  `tests/test_product_ratchet.py`.
- Запись файла через shell-heredoc портила обратные слэши и переводы строк в строках и файлы (9 повторов, последний
  2026-10-04) →
  хук `plugin/hooks/guard_shell_writes.py` (запись файлов проекта только Write и Edit), тест
  `tests/test_shell_writes.py`.
