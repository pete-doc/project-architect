# BACKLOG — мелкие найденные обходы и неудобства

До пилота на fm26-data действует заморозка: новых проверок, доработок табло и CI нет. Найденное записывается сюда
одной строкой и не исправляется. Разбираем после пилота вместе с его результатами.

Формат строки: дата, что найдено, чем это грозит.

- 2026-10-03: правка текста ADR не запускает тесты, которые читают ADR (их ловит только следующий PR с кодом). Грозит: опечатка в ADR доживает до следующего PR.
- 2026-10-03: перевод PR в черновик и обратно (запрос `full-run`) отменяет включённое автослияние. Грозит: после зелёного `full-run` PR надо сливать вручную, он сам не сольётся.
- 2026-10-03: PR, меняющий общий код проверок или сам CI, гоняет в «быстрой» части тесты всех языков, то есть почти полный прогон. Грозит: такой PR платит почти дважды.
- 2026-10-03: на табло прогоны веток без PR (пробные ветки) попадают в строку «вне PR». Грозит: «вне PR» завышено.
- 2026-10-03: карточка `analyze-existing` считает нарушением P13 задание на Windows и workflow с `push` (например, `state.yml`). Грозит: лишнее замечание, агент должен уточнить по тексту.
- 2026-10-03: в истории `main` и в ссылках прежних PR остался прежний личный email (решение владельца: оставить как есть). Грозит: адрес виден в публичном репозитории.
- 2026-10-03: в PR только с текстом тесты не идут: опечатка в ADR или устаревший индекс ADR всплывёт в следующем PR с кодом. Грозит: поздняя находка мелкой ошибки.
- 2026-10-04: проба 1 `/parch:doctor` (rm -rf во временной папке) теперь разрешена исключением и ничего не доказывает; переделать после пилота на команду, которую `guard_destructive` блокирует всегда и которая безвредна (например, `git reset --hard` во временном git-проекте doctor). Грозит: проба 1 больше не проверяет hook.
- 2026-10-04: карточка `analyze-existing` занижает проекты с собственным устройством: не видит журнал решений в одном файле (`DECISIONS.md`, ищет только `docs/adr/`), отчёты о сбоях в `docs/incidents/` (ищет `state/incidents/`), цель в `master_plan.md`; пришлось уточнять оценки вручную.
